## Struktur dan integrasi

- `src/location/distance.js`: Haversine murni, hasil meter, koordinat tidak valid menghasilkan NaN.
- `src/location/geofence.js`: controller tanpa React; state kunjungan dan antrean; update menghasilkan event `{poiId, poi, visitId, distanceMeters}`.
- `src/poi/adapter.js`: validasi dan seam dataset PB03. Setiap ID duplikat dibuang seluruhnya agar identitas tidak ambigu. Tidak ada konversi string koordinat secara diam-diam.
- `src/hooks/useForegroundLocation.js`: satu watcher bersama, izin, layanan, pembacaan awal dan AppState; initial read memakai sumber lokasi yang sama, bukan watcher kedua.
- `src/hooks/usePoiTriggers.js`: hubungkan sampel ke controller dan kedaluwarsa tampilan setiap detik.
- `src/components/PoiTriggerModal.js`, `ActionButton.js`, `theme.js`: UI04 dan primitive tampilan.
- `src/dev/*`: fixture dan kontrol development; `tests/geofence.test.js`: pengujian logika.
- `App.js`: integrasi sementara pada layar GPS; tidak membangun peta atau detail.

PB03 harus menyediakan array data berikut, dalam WGS84 derajat desimal:

Validasi membatasi latitude ±90, longitude ±180, radius finite positif, field teks wajib; image hanya HTTP(S). Radius dan konten tempat perlu validasi tim survei.

## Kebijakan deteksi

- Masuk: jarak pusat GPS ≤ `triggerRadiusMeters` per POI. Fixture memakai A=12m dan B=15m.
- Status per POI: `inside`, `visitId`, `triggered`, bukti keluar. Satu event per kunjungan. Menutup modal hanya mengonsumsi antrean, tidak mengubah kunjungan.
- Keluar: jarak **> radius masuk + 8m**, minimal **2 sampel berbeda** yang berurutan dan durasi sejak sampel keluar pertama **≥2000ms**. Sampel kembali ke ambang keluar atau lebih dekat menghapus bukti keluar. Margin mengurangi pergantian status akibat noise di radius kecil; perlu tuning lapangan, bukan cooldown.
- Konfigurasi melalui parameter kedua `GeofenceController(pois, policy)`: `exitMarginMeters`, `exitSamples`, `exitDurationMs`, `maxAgeMs`, `maxAccuracyMeters`. Nilai harus positif finite; jumlah sampel integer ≥2.
- Sampel layak: koordinat valid, akurasi diketahui 0–25m, umur 0–15000ms. Sampel masa depan, invalid, tua atau buruk tidak mengubah status kunjungan dan memutus bukti keluar; tampilan/antrean dibuang. Sampel berulang atau lebih lama daripada sampel diterima terakhir diabaikan, tidak dihitung sebagai konfirmasi keluar.
- Ambang akurasi 25m sengaja tidak mewajibkan akurasi lebih kecil daripada radius 10–15m, supaya fitur tetap dapat dicoba pada perangkat umum. Akurasi **tidak** ditambahkan ke radius masuk; keputusan memakai estimasi pusat GPS. Ini kompromi yang masih bisa menghasilkan false positive/negative di jalan sempit. Harus dikalibrasi lewat uji lapangan.
- Antrean: event satu pembaruan diurutkan jarak lalu ID (perbandingan leksikal), batch berikutnya FIFO. Hanya kepala antrean terlihat. Setiap pembaruan, setiap detik, sebelum dismiss dan sebelum menampilkan modal, relevansi diperiksa ulang terhadap umur/kualitas sampel, ID kunjungan dan **radius masuk**. Item yang keluar radius masuk dibuang meski status inside masih dipertahankan hysteresis. Item yang dibuang telah mengonsumsi trigger kunjungan; tidak diputar ulang ketika jitter kembali masuk.
- Aplikasi tidak aktif: watcher dilepas, tampilan/antrean dibuang, bukti keluar dibatalkan, status kunjungan tetap di memori. Saat kembali aktif, minta/periksa izin dan layanan lagi, mulai watcher baru dan baca posisi baru; kunjungan lama tidak otomatis dipicu ulang. Jika pengguna keluar dan masuk saat aplikasi tidak aktif, pergerakan itu tidak dapat dibuktikan sehingga tidak rearm. Keluar terkonfirmasi saat aktif diperlukan.
- Restart proses, remount host, atau pergantian dataset/sumber simulasi: status memori direset. Posisi pertama yang layak di dalam POI adalah kunjungan baru. Tidak ada pelacakan background, push atau persistensi koordinat.
- Async GPS dilindungi cancellation dan session token; subscription yang selesai setelah cleanup langsung dilepas, hasil sesi lama tidak dipakai. Watcher dimulai sebelum initial read supaya kegagalan initial read tidak mematikan pemantauan. Kegagalan awal/layanan/izin dapat dicoba lagi; tanpa fix awal selama 20 detik ditampilkan pesan kegagalan, watcher tetap dapat pulih.

## Batas verifikasi dan checklist perangkat

Pengujian otomatis memeriksa jarak, masuk/keluar, dismiss, jitter, kualitas/umur/urutan sampel, state per POI, urutan/deduplikasi/relevansi antrean, reset sesi, adapter dan konfigurasi. Lint/typecheck dan export bundle tidak membuktikan perilaku perangkat.

Sebelum penerimaan perangkat/lapangan, periksa:

1. Android dan iOS: izin ditolak, layanan mati, retry, sinyal hilang/lambat, kembali aktif dan restart proses. Pastikan tidak ada watcher ganda setelah pergantian sumber/aktif berulang.
2. Modal: Android back, VoiceOver/TalkBack, nama/deskripsi panjang, ukuran font besar, layar pendek, safe area/notch, foto valid serta URL rusak dan fallback.
3. Simulasi: urutan A/B, tutup saat masih di dalam, keluar dua sampel lalu masuk ulang, serta callback ID detail.
4. Lapangan Braga dengan koordinat PB03 tervalidasi: radius 10–15m, akurasi GPS dan jitter di koridor bangunan; evaluasi margin 8m/konfirmasi 2s dan batas kualitas 25m.

Belum ada klaim pengujian perangkat, UI native, halaman detail, peta, atau lapangan.
