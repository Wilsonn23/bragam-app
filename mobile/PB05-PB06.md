## API contract

Backend SELECT includes `cooldown_seconds` and `notification_body`. Response example (illustrative content only):

```js
{
  id: 'P01', name: 'Nama POI', category: 'Kategori',
  latitude: -6.91775, longitude: 107.60912,
  triggerRadiusMeters: 10, cooldownSeconds: 60,
  description: 'Deskripsi POI', shortDescription: 'Deskripsi POI',
  notificationTitle: 'Judul notifikasi', notificationBody: null
}
```

Adapter accepts camelCase API fields and snake_case database fields. Numeric coordinate strings are converted; blank/null/non-finite/out-of-range coordinates and invalid radii are rejected. Duplicate IDs are excluded, but **distinct IDs with identical coordinates are preserved**. The fetch boundary rejects partial-invalid datasets explicitly. Cooldown defaults to 60 only when absent/invalid; valid custom values, including zero, are respected. An empty description is safe and gets neutral fallback copy. Optional image URL must be HTTP(S); missing/failed image uses a local visual fallback. The current database has no photo column and no place-specific photos were found locally. Existing Figma assets are icons/placeholders, not POI photos.

Notification title uses notificationTitle then POI-name fallback. Body uses nonempty notificationBody then a description summary (maximum about 220 characters), then neutral fallback. Database IDs and coordinates are never replaced. API audio metadata aliases are preserved for the existing detail integration.

## Visit and cooldown policy

- Enter: Haversine distance in meters ≤ each POI's radius (database 10/12/15m).
- Visit state is per ID: inside/outside, visitId, consumed trigger, lastTriggerAt, exit evidence. Dismissal never changes visit state.
- Confirm exit: distance > radius + **8m**, at least **2 distinct consecutive fixes** spanning **≥2000ms**. A closer fix, bad fix, suspension or >15s sample gap breaks exit evidence. Policy remains configurable in GeofenceController.
- Cooldown is the minimum wall-clock interval between emitted events for the same ID, normally **60s**. A re-entry during cooldown consumes that visit without emitting. Waiting inside beyond expiry does not emit. Exit again and re-enter after cooldown to trigger. Another POI has independent state/cooldown.
- Accept only valid coordinates, known accuracy **0–25m**, sample age **0–15000ms**. Future/invalid/poor/stale fixes cannot trigger. Duplicate/out-of-order timestamps cannot confirm exit. 25m deliberately avoids requiring precision smaller than the 10–15m entry radius; center-distance decisions still need field calibration and can be inaccurate among buildings. Accuracy does not enlarge the entry radius.
- Events from one update are sorted by distance then lexical ID; subsequent batches are FIFO, no duplicate (ID,visitId). Only queue head appears. Every update, each second, and before dismiss/presentation prune by current sample age/quality, matching visit and **entry** radius. A discarded event stays consumed for that visit, avoiding jitter spam.
- Only active foreground Explore detects. Leaving the tab/root or opening detail stops the watcher and clears presentation/exit evidence, keeping visit/cooldown state while host stays mounted. Background return reads a new fix; unobserved exits during background do not rearm. Process restart, host remount or switching the explicit development dataset starts a new in-memory session.
- One Expo location subscription is shared; Explore's native map location tracking is disabled and it displays the shared position marker. Async permission/subscription/read completions are ignored after stop; a late-created subscription is removed. The initial one-shot read cannot overwrite a newer watcher fix. A 20s initial timeout shows recoverable error while the watcher can still recover.
